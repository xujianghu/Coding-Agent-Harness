# 固定仓库修复评测

本目录包含 10 个无外部依赖的 Node 仓库任务，覆盖边界条件、多文件修复、代码定位、回归与异步逻辑。每项任务包含只给 Agent 的 `workspace`、仅供独立评分的 `acceptance`，以及离线自检专用的 `mock-solution`。任务难度属于入门级；完成这些任务不能据此宣称已达到真实大型仓库的修复水平。

构建后，从仓库根目录运行：

```powershell
npm run build
node dist/eval/cli.js --mock --mode all --repeat 1
```

`--mock` 不读取模型凭据、不调用模型，由固定脚本执行搜索、失败测试、源码写入、回归测试与独立验收。此模式在本地临时目录执行固定代码，仅验证评测机制；报告明确标记为 `mock-mechanism-check`，不输出模型成功率。固定修复内容不会进入真实 Agent 的工具可访问目录。

真实评测使用现有配置和凭据机制，包括供应商环境变量与 `.harness/credentials`。先准备配置、正常模型凭据，以及已拉取到本地的 `node:22-alpine` 镜像，再运行：

```powershell
docker pull node:22-alpine
node dist/eval/cli.js --config .harness/config.yaml --mode all --repeat 3
```

真实运行会产生配置供应商的正常 API 费用。本轮工程验证未执行真实付费模型请求；仓库中没有真实模型成功率数据。Docker 不可用或镜像未缓存时会明确退出，绝不静默切换到宿主执行。

`--tasks 01-clamp,05-cart` 可筛选任务，`--output .harness/eval-results` 指定报告根目录。不同模式、任务和重复尝试均重新创建干净工作区；Agent 仅获得任务说明、源码与公开测试，不挂载隐藏验收或修复脚本。

| 模式 | 工具结果 | 模型声明完成后的处理 | 最终评分 |
|---|---|---|---|
| full | 保留成功结果与失败诊断 | 运行公开回归测试，失败详情反馈给模型，继续修复 | 独立隐藏验收 |
| baseline | 保留成功结果与失败诊断 | 基础工具循环，声明完成即停止 | 独立隐藏验收 |
| no-feedback | 保留成功结果、调用 ID 与失败状态，删除失败诊断 | 运行公开回归测试，失败只反馈通用失败状态，继续修复 | 独立隐藏验收 |

三个模式使用相同工具、模型、温度、单次输出上限、上下文配置和每任务总 Token／轮数／超时预算。默认缺失总 Token 配置时统一设为 100000。baseline 未花完的预算不补跑；成功率与实际用量同时统计。不同策略自然会产生不同上下文长度，这是实验变量，实际 Token 使用量会单独记录。

公开测试反馈与隐藏评分相互独立。隐藏断言由可信父进程执行，父进程通过受限 JSON RPC 向独立候选进程传入函数参数并检查返回数据；父进程不加载候选源码。候选 Docker 容器只读挂载源码与 RPC 服务，不挂载隐藏验收，断网、移除 capabilities、限制 CPU／内存／PID、设置非 root 用户。协议保留 NaN、对象共享引用、无原型对象、异常类型与调用后的输入数据；异步 retry 的回调由结构化步骤描述在候选进程内构造。候选打印成功标记、提前退出或伪造未知 RPC ID 都不能使父进程通过断言。超时与取消会等待候选进程终止及容器删除后返回。

评分先逐文件比较：仅 `allowedChanges` 中的现有源码文件可以变化；新增文件、修改公开测试、README 或 package.json 均导致失败。符号链接及特殊文件拒绝评分。隐藏验收通过且 Agent 正常完成后才计为成功；空输出、模型错误、超时、预算耗尽与验收失败均计入已开始任务的分母。

评分使用已校验内容的独立临时副本。Linux 非 root 宿主使用相同 UID／GID 的非 root 候选容器，副本保持 `0700`／`0600` 私有权限；宿主为 root 或 Windows 时，候选使用 UID 65534，自建副本目录和文件设为 `0755`／`0644`。原始工作区权限不变。副本与 RPC 服务都只读挂载，完成或失败后统一清理。

每次运行生成独立目录：

- `run.json`：任务清单哈希、Harness 提交／工作区状态／源码哈希、模型和全部统一预算。
- `policy.json`：本次实际使用的治理规则、统一工具白名单与端点哈希。
- `results.jsonl`：每次尝试一条记录，包含失败原因、真实／估算 Token、耗时、工具次数、费用与验收结果。
- `report.md`：按模式汇总模型评测；离线机制结果单列，不混入模型成功率。
- 每次尝试的 `trace.jsonl`、`changes.diff`、`candidate/`：完整模型交互、治理决策、工具结果、公开验证、隐藏评分与最终候选代码。

`realUsage` 只累计供应商确实返回的 Token 用量；缺失的调用用量单列到 `estimatedUsage`，并设置 `usageEstimated=true`。没有核实定价时 `cost=null`。模型请求异常且没有返回用量时设置 `usageUnavailable=true`，不伪造账单数据。

清单哈希覆盖任务说明、原始仓库、公开测试、隐藏验收和离线脚本。评测冻结后修改任何内容都会改变哈希；正式对照应保持哈希、Harness 版本、模型与预算一致，保存全部尝试。当前任务数很少，建议先运行机制自检，再以每任务每模式至少 3 次的真实运行获得初步数据，并继续补充真实仓库任务和失败复盘。
