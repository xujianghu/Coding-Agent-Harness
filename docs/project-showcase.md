# 项目展示与简历表达

项目定位：可验证、可恢复的编码 Agent 执行框架，配套本地 React 会话工作台。展示重点是连续任务上下文、工具协议、执行治理、验收、检查点与评测。

## 五分钟演示

从升级分支安装并运行 `npm run build`，然后启动 `npm run web`，打开终端中的本地地址。界面左侧是会话列表，中间是连续对话与输入框，右侧是只读文件、Diff 和执行详情。

1. 新建机制演示会话，说明空会话创建只保存记录，不调用模型。该会话使用独立演示目录、本地执行和固定验收，创建后不会切换到真实模型。
2. 发送“修复金额计算错误，并运行测试验证”。查看创建和读取 `amount.js`、将加法改为乘法的真实工具事件，在测试审批处批准本次执行。
3. 查看运行结束与验收通过两个状态，再打开右侧文件和 Diff：文件是当前磁盘内容，Diff 是所选 run 的修改前后预览，轮次和 Token 估算是本次运行统计。
4. 在同一会话追加“为金额计算补充使用说明”。第二个 run 读取已修复文件，写入 `notes.md` 记录需求并再次申请验收；会话保留两轮消息和各自执行记录。说明这两轮来自预设响应，不能证明模型理解了任意需求。
5. 刷新页面或重启服务，检查会话与运行能够从本地记录载入。说明新消息创建新 run、使用新预算；恢复中断任务继续原 run、保留累计预算，已完成的 run 不能恢复。

可另建演示会话，在待审批时取消执行，再于系统允许恢复时继续原 run，查看取消和恢复轨迹。未完成工具调用会阻止追加新需求，但原 run 可以在安全检查通过后继续处理剩余调用；结果未知、工作区改变或预算耗尽时，恢复会显示明确的拒绝原因。

实时界面通过 SSE `event: run` 接收完整运行快照，展示工具活动、审批和完成状态；当前没有模型逐 Token 输出。文件面板只读，不具备网页编辑功能。服务固定一个启动工作区，本机单用户、同时只执行一个 run，不提供多项目或 Git worktree 切换。

评测部分可运行 `npm run eval:smoke`，在报告页查看三种模式结果；mock 只说明评测机制工作，没有真实模型尝试时，真实模型成功率显示为“—”。

真实任务通过工作区已有模型配置执行。将工作台启动到一个适合展示的小型测试仓库，提供明确的缺陷描述和验收命令；保留模型、初始代码、最终补丁、测试结果和调用轨迹，才能展示模型实际完成任务的过程。

## 可写入简历的实现贡献

以下表述描述当前实现，不包含尚未测得的模型成功率：

- 基于 TypeScript 实现编码 Agent Harness，接入三类提供商的原生工具调用，提供仓库搜索、精确补丁与测试工具；通过验收失败反馈驱动继续修复，区分模型结束与任务验证通过。
- 设计统一动作治理与 Docker 命令执行器，实现审批后策略重检、执行预算、取消清理和检查点恢复；构建 React 会话工作台，通过 SSE 展示执行快照，支持连续追加需求、人工审批、文件只读浏览与逐次 Diff。
- 构建 10 个冻结修复任务及独立隐藏验收，支持基础循环、完整反馈与无诊断反馈对照，记录每次尝试、补丁、模型用量与停止原因，并建立跨平台 CI 和安装包自检。

可根据简历篇幅保留其中两条。真实评测完成后，再将第三条改为含模型名称、任务数、重复次数、基线与改进结果的定量描述。

## 面试中需要解释的设计选择

| 设计 | 要解释的原因 | 对应实现 |
| --- | --- | --- |
| `completed` 与 `verified` 分离 | 模型宣告完成不能证明代码正确 | `src/core/loop.ts` |
| 审批后重新校验 | 审批只授权对应动作，仍受路径与命令边界约束 | `src/governance/pipeline.ts` |
| 工具消息成组裁剪 | 工具调用 ID 与结果必须保持对应 | `src/core/loop.ts` |
| 不确定执行拒绝恢复 | 避免重播已经发生但未确认的副作用 | `src/cli/checkpoint.ts` |
| 独立隐藏验收 | 候选实现不能通过修改公开测试或打印成功文字改变评分 | `src/eval/grader.ts` |
| 记录运行来源 | 离线机制检查不能被误标为真实模型任务，恢复也不能隐式切换模式 | `src/web/manager.ts` |
| 会话与 run 分开 | 新需求继承安全上下文并开启新预算，恢复继续旧预算 | `src/web/manager.ts`、`src/core/conversation-context.ts` |
| SSE 完整快照 | 执行状态可实时更新，慢客户端只需最新状态；不等同于模型 Token 流 | `src/web/server.ts` |
| 文件只读与差异预览 | 查看当前文件和本轮变更，不把浏览器变成任意路径读写入口 | `src/web/files.ts`、`src/web/changes.ts` |

## 真实评测的证据要求

在相同模型、初始任务、工具和预算下运行三种模式，并保存全部尝试。简历中的结果应能追溯到 `results.jsonl`、报告和对应轨迹；说明成功分母、重复次数、失败类别、实际用量和估算用量。

当前任务集是轻量 JavaScript 修复任务。若求职重点是 Java 与 Agent 交叉方向，后续可扩展冻结的 Maven 缺陷任务，并预先准备 JDK、Maven 和依赖镜像；需要单独记录这部分评测结果。
