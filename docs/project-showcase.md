# 项目展示与简历表达

项目定位：可验证、可恢复的编码 Agent 执行框架，配套本地 React 工作台。重点展示工具协议、反馈修复、执行治理、检查点与评测，而不是仅展示模型聊天界面。

## 五分钟演示

从升级分支安装并构建，运行 `npm run web`，打开终端中的地址。

1. 在任务工作台选择“机制演示”，提交默认金额计算修复任务。
2. 查看文件创建、读取、补丁和策略检查事件。演示在独立示例工作区使用固定模型响应，文件与测试操作真实执行。
3. 在测试审批处批准本次操作，观察“已完成”和“验收通过”两个独立状态，以及文件差异、轮次和 Token 估算。
4. 再启动一次演示，在审批处停止执行。从运行记录打开任务并恢复，再次批准测试；轨迹应保留取消与恢复事件，之前的文件操作不应重复执行。
5. 打开评测报告，查看 `npm run eval:smoke` 生成的三种模式报告。没有真实模型尝试时，真实模型成功率显示为“—”。

真实任务通过工作区已有模型配置执行。将工作台启动到一个适合展示的小型测试仓库，提供明确的缺陷描述和验收命令；保留模型、初始代码、最终补丁、测试结果和调用轨迹，才能展示模型实际完成任务的过程。

## 可写入简历的实现贡献

以下表述描述当前实现，不包含尚未测得的模型成功率：

- 基于 TypeScript 实现编码 Agent Harness，接入三类提供商的原生工具调用，提供仓库搜索、精确补丁与测试工具；通过验收失败反馈驱动继续修复，区分模型结束与任务验证通过。
- 设计统一动作治理与 Docker 命令执行器，实现审批后策略重检、执行预算、取消清理和检查点恢复；构建 React 工作台，展示任务轨迹、人工审批、代码差异与运行历史。
- 构建 10 个冻结修复任务及独立隐藏验收，支持基础循环、完整反馈与无诊断反馈对照，记录每次尝试、补丁、模型用量与停止原因，并建立跨平台 CI 和安装包自检。

可根据简历篇幅保留其中两条。真实评测完成后，再将第三条改为含模型名称、任务数、重复次数、基线与改进结果的定量描述。

## 面试中需要解释的设计选择

| 设计 | 要解释的原因 | 对应实现 |
| --- | --- | --- |
| `completed` 与 `verified` 分离 | 模型宣告完成不能证明代码正确 | `src/core/loop.ts` |
| 审批后重新校验 | 审批只授权对应动作，仍受路径与命令边界约束 | `src/governance/pipeline.ts` |
| 工具消息成组裁剪 | 工具调用 ID 与结果必须保持对应 | `src/core/loop.ts` |
| 不确定执行拒绝恢复 | 避免重播已经发生但未确认的副作用 | `src/cli/checkpoint.ts` |
| 独立隐藏验收 | 候选实现不能通过修改公开测试或打印成功文字改变评分 | `src/eval/grader.ts` |
| 记录运行来源 | 离线机制检查不能被误标为真实模型任务，恢复也不能隐式切换模式 | `src/web/manager.ts` |

## 真实评测的证据要求

在相同模型、初始任务、工具和预算下运行三种模式，并保存全部尝试。简历中的结果应能追溯到 `results.jsonl`、报告和对应轨迹；说明成功分母、重复次数、失败类别、实际用量和估算用量。

当前任务集是轻量 JavaScript 修复任务。若求职重点是 Java 与 Agent 交叉方向，后续可扩展冻结的 Maven 缺陷任务，并预先准备 JDK、Maven 和依赖镜像；需要单独记录这部分评测结果。
