# 改进路线

[返回项目首页](../README.md) · [当前架构](architecture.md)

文档更新：2026-10-13。

以下内容是后续计划。当前版本已有工具治理、Docker 命令隔离、验收反馈、检查点、本地项目选择与切换、会话工作台和固定任务评测；本页列出的新增能力尚未作为交付成果。

## P0：证明和改善真实编码效果

| 方向 | 工作内容 | 完成条件 |
| --- | --- | --- |
| 真实模型评测与 Java 场景 | 扩展 Java/Maven 缺陷修复、多文件修改和测试失败定位任务；固定模型、任务与预算，对比 `baseline`、`full` 和 `no-feedback` | 保存全部尝试、隐藏验收结果、失败类别、耗时和模型用量；任何成功率结论均可追溯到报告 |
| 仓库理解与上下文管理 | 增加目录与符号索引、按需检索和结构化任务摘要；保留需求、约束、修改记录、失败验证和待办 | 压缩后工具调用与结果仍成对；用固定任务比较长任务成功率与 Token 消耗，记录收益和退化 |

现有 mock 机制自检不能作为真实模型能力结果。Token 估算值与提供商返回的实际用量应分别统计；未核实费用时保持未知。

## P1：完成可使用的开发流程

| 方向 | 工作内容 | 完成条件 |
| --- | --- | --- |
| 会话独立工作树 | 在已有本地项目切换上，为任务选择基准提交、分支和 Git worktree | 不同任务修改同一文件时互不覆盖；生命周期、清理与冲突处理可验证 |
| 修改审查与交付 | 增加修改评论、选择接受或撤销、提交和 PR 草稿流程 | 拒绝过期 Diff，撤销不覆盖用户原有修改；交付关联实际测试与最终补丁 |
| 模型流式输出与执行中指导 | 适配提供商增量文本与工具参数，支持排队消息和安全边界上的新约束 | 只执行完整且经过校验的工具调用；断流、取消和恢复不会重复执行动作 |

Git worktree 用于隔离代码修改，不能替代 Docker 对命令执行环境的隔离。

## P2：扩展与量化

- **Skills / MCP**：沉淀可复用的 Java 修复、测试和审查流程，接入有实际用途的工具；权限、超时与调用结果纳入统一治理和轨迹。
- **计划与受控多 Agent**：先支持结构化计划、检查点与并行只读探索，再扩展并行修改；子任务有明确职责和预算，与单 Agent 对照评测。
- **效果与成本面板**：在已有轨迹和用量记录上增加跨版本比较、失败分类、阶段耗时与失败轨迹查看。
- **浏览器验收**：针对前端任务形成修改、启动、页面检查和再次修复的流程，保留截图与可复现证据。

## P3：运行平台

在核心任务效果稳定后，再评估定时自动化、云端运行、多用户协作与资源配额。当前本地工作台面向回环地址上的单用户使用，未提供这些能力。

优先交付真实评测、上下文管理和 Git 工作流；每项改进都应回答它解决了哪类失败，以及效果是否能复现。
